# 阿里云 AnalyticDB 智能运维进化之路：AI 助手如何重塑数据库诊断体验

> 阿里云正式推出 [ADB MySQL](https://help.aliyun.com/zh/analyticdb/analyticdb-for-mysql/product-overview/what-is-analyticdb-for-mysql) AI 助手——一款专为分析型数据库打造的 AI 运维引擎，深度集成于 ADB MySQL 控制台，标志着 ADB MySQL 实例运维正式迈入"AI 决策"新阶段。

---

## 一、前言

在企业数字化转型加速的今天，[实时数据分析](https://help.aliyun.com/zh/analyticdb/analyticdb-for-mysql/use-cases/real-time-data-analysis/)已成为业务决策的核心支撑。作为阿里云自研的云原生分析型数据库，云原生数据仓库 AnalyticDB MySQL 版（简称 ADB MySQL）凭借高性能、高并发和强 SQL 兼容能力，广泛应用于实时 BI、用户行为分析等典型 OLAP 场景。

然而，随着业务复杂度提升，SQL 查询也日益多样，性能问题随之而来：一条看似简单的分析语句，可能因数据分布、索引缺失或执行计划不佳而响应缓慢。传统依赖人工经验的调优方式，已难以满足高效运维的需求。

为此，阿里云正式推出 **ADB MySQL AI 助手**，深度集成于 ADB MySQL 控制台。

---

## 二、功能亮点

### 2.1 多轮智能问答

支持多轮自然语言对话，像和一位懂产品的技术专家实时交流：

- 不确定某个功能怎么用？直接问。
- 想知道最佳实践？它会结合场景给出建议。
- 复杂操作或配置时，自动附上官方文档链接，一键直达权威指引。

核心能力：
- 支持上下文理解，可连续追问
- 回答基于 ADB MySQL 真实产品逻辑，非通用话术
- 所有用户开箱即用，无需额外权限

**使用方式**：登录 ADB MySQL 控制台 → 打开右侧「ADB MySQL AI 助手」



### 2.2 空间智能诊断

一键洞察存储隐患，精准输出优化建议。

传统数据库管理中，空间问题往往依赖人工排查，耗时耗力且容易遗漏。现在，ADB MySQL AI 助手全新上线「AI 空间智能诊断」功能：

- 在 AI 助手点击一次，自动扫描实例空间状态
- 输出多维度空间诊断结论和可落地的优化建议
- 诊断结论以结构化表格 + 可操作建议形式呈现
- 支持一键跳转至对应优化入口
- 根据业务趋势动态调整建议优先级



### 2.3 单 SQL 查询诊断

慢查询不用再提工单，AI 助手快速给出答案。

在传统的托管数据库服务中，用户无法查看底层执行日志、资源指标或执行计划细节，一旦查询变慢，唯一的选择就是提交工单。

现在，ADB MySQL AI 助手全新上线「单 SQL 查询诊断」功能：

- 无需提工单，无需等待
- 自动解析慢查询根因，提供清晰、可操作的优化建议
- 就像有一位资深 DBA 在你身边实时指导

在「[SQL 诊断优化](https://help.aliyun.com/zh/analyticdb/analyticdb-for-mysql/user-guide/performance-tuning/)」和「SQL 审计」页面，选中任意一条 SQL 记录，点击"AI 诊断"，即可生成三段式诊断报告。

### 2.4 双 SQL 查询对比

精准定位性能差异根源。

在传统数据库运维中，面对查询性能波动，往往只能靠经验猜测或逐项排查——看执行计划、看各种指标、再手动比对。

现在，ADB MySQL AI 助手全新上线「双 SQL 查询对比」功能：

- 输入两条 SQL 的查询 ID（可跨时间窗口或跨环境）
- 自动从执行计划、资源消耗、数据扫描量和实际耗时等多维度进行深度对比
- 直观呈现性能差异的关键因素

核心能力：
- 对比同一 SQL 在不同时间点的执行表现，识别资源波动（CPU 饱和、I/O 打满）
- 对比相似 SQL 在不同环境下的执行差异，判断是否因配置、索引、数据量变化导致性能偏差
- 自动高亮关键差异点：扫描行数突增、临时表使用、锁等待时长、I/O 消耗飙升等
- 输出清晰的对比报告，指出"为什么变慢"、"谁在拖后腿"，并提供优化建议


**使用方式**：
1. 在 ADB MySQL 公共云控制台，右上角打开「ADB MySQL AI 助手」


2. 对话框工具栏打开 AI 智能诊断，诊断场景选择「SQL 查询对比」


3. 输入「基准查询 ID」和「对比查询 ID」，点击"提交分析"


### 2.5 实例 CPU 使用率分析

精准识别异常波动与资源瓶颈。

面向 ADB MySQL 实例运行状态的核心资源[监控](https://help.aliyun.com/zh/analyticdb/analyticdb-for-mysql/user-guide/monitoring-and-alerting/)能力，专注于实例级别的 CPU 资源健康状态分析。通过持续采集并深度解析 CPU 使用率等关键指标，实现对 CPU 资源使用趋势的实时洞察与异常识别。

### 2.6 实例查询、写入诊断

实例级维度一键定位根因。

面向 ADB MySQL 实例运行状态的两类核心性能分析能力，旨在从资源使用层面识别并解释因系统级异常（如 CPU、内存、磁盘或 I/O 资源打满或剧烈波动）所引发的上层业务问题。

**实例查询诊断**：聚焦查询类性能劣化场景。当用户观察到查询响应变慢、执行超时、结果返回异常或查询失败等现象时，自动关联实例在对应时间段内的资源指标（CPU 使用率突增、内存压力升高、I/O 延迟上升等），判断是否存在资源瓶颈，并定位可能的根因。

**实例写入诊断**：专注于写入链路的稳定性与效率分析。当出现写入延迟增高、DTS 同步滞后、Truncate 操作超时或失败、INSERT/REPLACE 语句报错、批量写入吞吐下降等异常时，结合写入 TPS 趋势、磁盘使用率、I/O 队列深度、锁等待情况等指标，评估是否存在资源争抢或容量限制。

两类诊断均以实例为单位进行全局分析，不依赖单条 SQL 上下文，适用于快速判断"是否为资源问题"以及"资源问题影响了哪些业务行为"。
